## 不导入

## 旧 harness 的具体修正

1. 旧 runner 在条件表达式里调用执行函数，失败后仍可能走到显式成功返回，导致失败命令“通过”。新入口显式检查 subprocess 状态。
2. 旧 Node script 探测没有切到被检查项目目录，可能读取启动目录的 package.json。新入口把每个项目的 cwd 写入配置。
3. 不把所有一级目录当作可执行项目。新模板使用明确登记的项目清单，避免误扫资料目录。
4. 空项目和缺失检查不会冒充成功。初始 check 返回 NOT_CONFIGURED，等待项目实际命令。
5. 不把所有阶段都自动执行一遍，也不在检查时安装依赖。新项目按实际风险和 CI 入口配置必要检查。

## 证据边界

本次详细读取与比较的是导航、harness、维护脚本和选定的工程 lesson，未声称逐字审计原目录的所有业务文档。原始私密出处映射仅留在作者本地审阅记录。本包附带的测试验证新工具的实际行为，不验证所有历史事故的完整业务细节。
