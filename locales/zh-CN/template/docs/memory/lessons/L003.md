# L003 · 失败与空结果必须区分

状态、检索标签与复核日期以 [登记表](../lessons.json) 为准。

- **适用 / 触发**：读取外部数据、缓存刷新或运行验证。
- **原因**：吞异常可能把错误结果缓存、发布，或误导写入逻辑。
- **原则**：读取失败不能伪装成空值、默认内容或成功，恢复策略必须显式且可观测。
- **处理**：按空值、不可用和错误建模；需要降级时明确其范围与可见信号。
- **验证**：注入读取失败，断言失败传播且不覆盖最后一份有效数据。
- **失效 / 复核条件**：业务明确采用新的降级策略时重新评估，而非一律禁用所有 fallback。

来源为经过脱敏和重写的历史工程经验，见 [导入评审](../IMPORT_REVIEW.md)。具体技术实现必须在新项目中核实。
