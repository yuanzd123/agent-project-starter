# 架构

[English](ARCHITECTURE.md) · [分层工作流指南](WORKFLOW.zh-CN.md)

项目有独立 Prompt 和可执行脚手架两个入口，任一可单独使用。可选 workflow 在共享记忆和显式验收之上增加串行角色调度，无需采用大型多代理框架。

## 组件

- tools/bootstrap.py：在英文模板上覆盖语言内容，先检查冲突和符号链接边界，再创建缺失文件，不安装软件或修改 Git 配置。
- template/harness/run.py：验证显式项目配置，在登记目录执行 argv 参数数组，失败即停止；整项目 check 也校验 memory。
- template/scripts/memory.py：验证登记表、生成索引，按标签、状态、复核日期和大小限制检索 active lessons。
- template/workflow/：可选串行调度器，包含任务依赖校验、风险路由、调用／补丁日志、预算、fake／JSON CLI 适配器、整体验证和独立只读审查。复用 harness 配置校验和 memory brief。
- tools/demo.py：原有临时项目检查／记忆演示。tools/workflow_demo.py 演示离线工作流，tools/workflow_benchmark.py 比较报告。
- tools/check_locales.py 和 tools/check_docs.py：验证语言组装、生命周期一致性和本地文档链接。

## 明确边界

Harness 不推断并运行任意目录的命令，初始化 Prompt 要求先检查真实清单。配置命令属于可信可执行输入，不受 OS 沙箱隔离。索引只是登记表的视图，LATEST 保存当前状态，lesson 正文解释可复用原因；私人缓存不是另一份项目权威。

英文是基础模板。locale 只替换人类阅读内容，运行代码和许可证共享。CI 校验两种组装结果。

## 工程选择

| 选择 | 原因 | 重审条件 |
| --- | --- | --- |
| Python 标准库 | 安装面小、行为可读 | 依赖确实减少足够复杂度 |
| Markdown + JSON | 可审阅、可迁移、无需服务 | 结构化查询成为真实需求 |
| 显式标签 | 可预测、开销小 | 真实漏检说明需要更强检索 |
| 不自动上传 | 数据与发布权限明确 | 另有显式可选流程 |
| 可选串行调度 | 保留轻量入口，依赖不要求并行框架 | 测量证明并行实现值得投入 |
| 冲突优先安装 | 保护既有内容 | 有可保留定制的审阅式迁移 |

## 可选执行的取舍

角色映射操作者登记的逻辑档位，不硬编码商业型号。CLI 适配器采用明确 JSON 协议，核心保持标准库。供应商 SDK／专用预设和付费联调不在本 MVP 的已验证范围；模拟模式在报告中明确标注。

整个工作目录有单 writer 锁。外部调用前持久化操作编号和预算预留，恢复时复用三类角色已返回的响应；中断中的调用保留 uncertain。补丁先保存前置哈希和 diff，再原子替换文件。这是崩溃恢复机制，不是沙箱或分布式事务。

检查使用可信 argv、显式 cwd 和超时。只有显式分类为代码错误的失败才能修复／升级；基础设施、依赖、需求歧义直接阻塞。所有任务在整合后版本接受最终检查和只读审查，验收绑定内容／配置哈希。审查不能覆盖失败检查；配置／harness 改变需新 run，源码变化使已有验收过期。合法规则变更必须有明确范围和独立批准。

原始运行证据保存在忽略的 .local，不自动向共享 lessons 导入状态、凭据、服务权限、绝对路径或私人历史。安装器继续先检查冲突，两种语言使用同一份运行代码。

## 验证证据

回归覆盖既有安装、记忆、harness、中文流程，以及调度、预算、恢复、真实 CLI 协议 mock、进程清理、越界与验收失效。离线演示使用真实命令和预期失败。CI 文件存在不等于 CI 已经通过；本地结果和平台／服务未验证范围须分开报告。
