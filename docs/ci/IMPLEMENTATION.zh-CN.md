# 已审查 CI：离线校验实现

状态：**已实现离线校验函数，尚无生产控制端、已批准运行环境或正式 CI 验收门禁。**

[English specification](IMPLEMENTATION.md) · [整体方案](../CI_TOOLCHAIN_PLAN.zh-CN.md) · [环境调查](HOSTED_ENVIRONMENTS.md)

## 已完成的部分

[tools/reviewed_ci.py](../../tools/reviewed_ci.py) 只使用 Python 标准库，没有子进程、安装器、联网、发布 GitHub 检查或执行候选代码的入口。它可以校验：

- 完整的 Linux／macOS／Windows × Python 3.10／3.13 六组记录，分别保持 x64／arm64／x64 架构。
- 精确解释器版本和绝对路径、镜像与完整发行包身份、七类工具链组件的来源证据引用、明确审批、支持周期审查和有效期。
- 独立采集的执行前环境观察值与清单一致，包括原生组件清单；解释器缺失和身份变化有不同错误类别。
- 同一仓库、PR、base、head、候选 tree、控制端、清单摘要、run 与 run attempt 下的六组完整成功结果。每组必须包含既有六条命令、整数零退出码和日志摘要。缺失、跳过、取消、超时、重复或不一致均阻塞。
- 清单原始字节与可信调用方提供的 SHA-256 一致；拒绝重复 JSON 键、非 JSON 常量、未知字段、必填 null、相对解释器路径及缩写修订号。

提交的[审批清单](approved-environments.json)保持为空。实际运行校验会以 **2** 退出并报告 `POLICY_UNAPPROVED`，不会发现什么就自动批准什么。

## 信任边界

**这些函数检查数据一致性，不能证明数据真实性。** 字段完整的伪造审批或伪造 job 记录，需要独立可信来源才能与真实记录区分。预期摘要、最新提交和托管服务的 job 元数据必须由候选无法修改的控制端取得。对候选提交的 JSON 自己计算哈希，再拿该哈希校验它，不会建立信任。

校验模块自身也需要已可信的引导 Python 及标准库。`-I -S` 可减少启动导入，不能批准解释器或隔离操作系统。本实现未指定任何运行环境为已批准。

尚未实现：采集真实机器信息、哈希完整已安装发行包、核实证据文档及实际加载的原生依赖、网络隔离、准备源码、执行候选测试、认证 GitHub 响应、发布必需检查或防止最终合并竞态。正式控制端必须先完成并验证这些边界，才能将本模块用于验收。CLI 成功或合成样本通过均不能授权合并。

测试在当前开发主机校验 Windows／macOS 的**数据记录**，未在这两个系统执行。拒绝候选输出 `PASS` 的用例仅验证输入结构，不证明候选无法伪造控制端证据；后者依赖尚未实现的隔离控制端和可信发布端。

## 数据接口

原有[方案契约](toolchain-contract.example.json)仍是非运行设计文档，不作为实际清单读取。新清单仅包含 `schema_version: 1`、`repository` 和 `approved_environments`。

每组记录包括 `matrix_cell`、runner 标签、镜像发布版本、固定架构、镜像身份证据／引导审查／平台信任边界摘要、Python 版本／绝对路径／可执行文件及发行包摘要、七类组件，以及审批结论、审批人、UTC 审查与过期时间、审批证据及支持周期审查摘要。

七类组件必须齐全：runner、bootstrap-shell、git、python、stdlib、native-extensions、dynamic-dependencies。每类需要精确版本、HTTPS 源码仓库、完整 40 位 Git 修订号，以及构建配方、依赖清单、产物清单、源码到产物证据和副作用审查的 SHA-256。第一版只支持 Git 源码修订；其他来源标识需要明确修改 schema。Python 组件版本和产物清单必须与解释器记录一致。字段齐全不能证明覆盖了全部加载依赖，实际来源审查仍须核实。

支持周期审查应涵盖当前安全公告和生命周期。Python 3.10 已停止支持，填写摘要不能代替保留旧版兼容测试所需的明确决定；本次未授予此类决定或例外。

| 函数 | 行为 |
| --- | --- |
| `parse_pinned_json` | 对照独立固定的摘要校验原始字节，再严格解析 JSON |
| `validate_inventory` | 校验六组清单及有效期，返回按组索引的记录 |
| `validate_observation` | 将可信执行前测量与已校验清单比较，不调用待验解释器探测版本 |
| `validate_results` | 内部校验清单字节摘要，检查 base/head 未变、六组 job 和所有命令完整成功 |

精确字段及类型见[英文接口说明](IMPLEMENTATION.md#data-interface-version-1)。结果同时绑定 `run_id` 和 `run_attempt`，防止跨重试混用记录；job ID 必须唯一。候选 tree 和父提交的真实性需要调用方独立核实。环境观察值包含解释器是否存在和七类组件产物清单，应在执行候选前独立取得，不能从候选输出目录读取。

## 验证及上线前提

使用已有、已审查的开发解释器运行常规回归；没有新增软件包依赖。专项命令为：

```text
python -m unittest discover -s tests -p test_reviewed_ci.py -v
```

对独立取得摘要的清单可调用 `python -I -S tools/reviewed_ci.py INVENTORY --sha256 EXPECTED_DIGEST`。成功信息明确为 `OFFLINE_VALIDATION_ONLY`，不会发布 `Reviewed CI / acceptance`。

新增测试覆盖合成正例及缺组／缺组件、未批准／过期、null、JSON 歧义、清单替换、镜像／架构／版本／路径／原生清单变化、解释器缺失、提交或运行身份不符、重复 job、命令失败／缺失和日志不完整等反例。既有检查及 Windows 换行符回归保持完整。

2026-10-22 在 Linux 预装 CPython 3.12.14 上完成开发验证：94 项回归全部通过（原有 77 项加新增 17 项）；158 个本地文档目标有效；中英文各 21 条 lesson 检查通过；bootstrap 演示、离线工作流场景和策略比较均成功。未下载额外解释器或软件包。这只是本地开发证据，不能代替 Python 3.10／3.13 的六组实跑结果。

上线仍缺：已批准环境与引导证据、Python 3.10 支持周期决定、真实执行前测量和候选隔离、可信控制端及认证结果采集、六平台实跑、受控切换时的分支强制规则。[分阶段落地方案](../CI_TOOLCHAIN_PLAN.zh-CN.md#分阶段落地与回退)继续适用。当前 workflow 未修改，单独推送此分支不会启动既有 CI。
