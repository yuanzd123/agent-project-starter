# L008 · A configuration name is not a deployment identity

Status, tags, and review dates live in the [registry](../lessons.json).

- **Scope / trigger**: Building, previewing, releasing, rolling back, or configuring domains.
- **Cause**: Aliases, configuration files, candidates, and the running version are different objects.
- **Principle**: Verify the actual account, project, environment, candidate revision, and serving endpoint. Neither a filename nor a passing build proves deployment.
- **Action**: Verify targets and revisions explicitly in the release workflow. Reused evidence must match its bound objects.
- **Validation**: Confirm the final endpoint serves the intended revision; compare actual resource configuration where unchanged resources are a requirement.
- **Reconsider when**: Provider behavior, release topology, or command semantics change.
