# L012 · Test controls and destinations in the rendered product

Status, tags, and review dates live in the [registry](../lessons.json).

- **Scope / trigger**: Buttons, cards, anchors, and CMS-rendered pages change.
- **Cause**: Overlays, hover stacking, and fallback components can make correct-looking source code unusable.
- **Principle**: Use real control semantics and behavior. Check final destinations and the relevant keyboard, pointer, and touch interactions.
- **Action**: Use appropriate links and buttons, inspect the actual rendering path, and provide accessible names.
- **Validation**: Exercise changed paths. In-page targets should exist uniquely and be visible at the destination.
- **Reconsider when**: Routing or rendering changes. Adapt validation instead of assuming all products use static HTML.
