# L010 · Verify durable writes, not just successful responses

Status, tags, and review dates live in the [registry](../lessons.json).

- **Scope / trigger**: Transactions, balances, inventory, orders, and critical state updates.
- **Cause**: Reads on the same connection and in-memory responses can conceal a failed commit.
- **Principle**: Verify critical writes from a separate connection or transaction. Exercise concurrency, failure, and rollback instead of trusting returned objects.
- **Action**: Propagate commit errors, define transaction boundaries and retry conditions, and avoid blind retries on uncertain state.
- **Validation**: Inject commit failures and concurrency; verify storage through a fresh connection or after restarting the process.
- **Reconsider when**: The driver, transaction layer, or isolation level changes. Do not carry a driver-specific patch into every project.
