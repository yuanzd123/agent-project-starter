# L011 · Fix access rules without default privilege escalation

Status, tags, and review dates live in the [registry](../lessons.json).

- **Scope / trigger**: Access errors, administrative functionality, and multi-tenant behavior.
- **Cause**: Elevating a role may restore functionality while exposing data; hardcoded tenant rules can leak into other tenants.
- **Principle**: Keep intended role and tenant boundaries. Shared capabilities and tenant-specific parameters need separate ownership.
- **Action**: Fix the access rule with the expected least-privileged role. Resolve configuration using stable tenant identities.
- **Validation**: Test allowed, denied, cross-tenant, and unauthenticated paths.
- **Reconsider when**: An approved product change alters the role model or tenant boundaries.
