# L016 · Treat caches and background processes as build inputs

Status, tags, and review dates live in the [registry](../lessons.json).

- **Scope / trigger**: The same revision behaves differently, pages look stale, or builds contain unexpected files.
- **Cause**: Leftover processes can regenerate files during a build; cached output can hide edits.
- **Principle**: Isolate task-owned caches, outputs, and watchers. Investigate environment contamination before deleting shared resources.
- **Action**: Track ownership and use reproducible output directories. Stop and rebuild only the affected resources when needed.
- **Validation**: Compare isolated clean output with the actual artifact and check for other writers to the same directory.
- **Reconsider when**: The builder, cache keys, or process lifecycle changes.
