# L003 · Distinguish errors from empty results

Status, tags, and review dates live in the [registry](../lessons.json).

- **Scope / trigger**: Reading external data, refreshing caches, or running validation.
- **Cause**: Swallowed errors can cache or publish incorrect output and trigger unsafe writes.
- **Principle**: Do not turn read failures into empty values, default content, or success. Fallback behavior must be explicit and observable.
- **Action**: Model empty, unavailable, and failed states separately. Define the scope and signal of any intended fallback.
- **Validation**: Inject read failures and check that errors propagate without replacing the last valid data.
- **Reconsider when**: Reassess when the product intentionally changes its fallback policy; not every fallback is wrong.
