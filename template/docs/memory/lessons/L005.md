# L005 · Separate task ownership from shared-resource coordination

Status, tags, and review dates live in the [registry](../lessons.json).

- **Scope / trigger**: Multiple people or sessions work concurrently.
- **Cause**: Broad staging may include unfinished work; blocking all worktrees can force unrelated changes into one release.
- **Principle**: Preserve unrelated edits and stage exact task-owned paths. Isolate concurrent editing, and coordinate shared refs and deployment targets separately.
- **Action**: Inspect ownership first. Serialize shared targets only when needed; do not clean up other tasks' resources.
- **Validation**: Review the actual staged diff and final commit scope, not just the commit message.
- **Reconsider when**: A shared-editing agreement or an explicitly requested workspace-wide cleanup changes the scope.
