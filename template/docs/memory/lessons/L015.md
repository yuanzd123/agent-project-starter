# L015 · Control time and business time zones in tests

Status, tags, and review dates live in the [registry](../lessons.json).

- **Scope / trigger**: Bookings, deadlines, billing periods, caches, and expiry logic.
- **Cause**: Machine-local time and the current wall clock can make the same test alternate between success and failure.
- **Principle**: Use explicit clocks and business time zones. Cover midnight and daylight-saving boundaries instead of waiting or skipping flaky tests.
- **Action**: Inject time where possible and simulate it within isolated dependencies without refreshing real credentials.
- **Validation**: Use fixed boundary inputs to verify local dates and elapsed durations; check that real SDK refresh paths are not triggered.
- **Reconsider when**: Time-zone rules or the business definition of time changes.
