# L013 · Give technical lessons version scope and removal conditions

Status, tags, and review dates live in the [registry](../lessons.json).

- **Scope / trigger**: Upgrading dependencies, changing machines, moving projects, or importing lessons.
- **Cause**: Old bugs may be fixed; obsolete flags and machine paths can create new failures.
- **Principle**: Preserve the failure mechanism while rechecking version-specific commands and workarounds. Historical experience is not permanent truth.
- **Action**: Check actual versions, primary documentation, and a small reproduction. Keep unsupported claims as candidates.
- **Validation**: Reproduce the issue or verify the fix in the current target, then record when the workaround can be removed.
- **Reconsider when**: Any relevant dependency, platform, or behavior changes.

Distilled and rewritten from prior engineering experience. See the [import review](../IMPORT_REVIEW.md). Verify concrete implementation details in the target project.
